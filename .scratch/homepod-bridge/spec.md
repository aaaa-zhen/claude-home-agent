# HomePod Bridge Hardening Spec

## 要解决的问题

Home Agent 已能通过 Home Assistant 向客厅 HomePod 投送短语音，但能力发现、并发、成功判定、临时文件和依赖管理仍不可靠。用户需要后续指令直接、快速、可重复执行，而不是重新探索设备和现场写脚本。

## 方案

提供一个窄接口的 HomePod 发声适配器，并把它登记到 Home Agent 的 Home Assistant 工具与技能索引中。适配器串行化对同一 HomePod 的操作，动态发现局域网地址，使用单次临时媒体服务，输出机器可读结果，并在结束后恢复可恢复的播放器状态。

## 用户故事

- 作为用户，我想让 HomePod 说一句话，以便几秒内听到结果。
- 作为用户，我想连续发送两条播报，以便它们按顺序播放而不是端口冲突。
- 作为用户，我想在失败时得到准确反馈，而不是被告知已经播放。
- 作为用户，我不想让临时语音长期残留或在局域网中被目录浏览。
- 作为维护者，我想让新会话直接发现这个能力，并能在重装环境后恢复依赖。

## 实现决策

- 保留现有简洁调用方式，新增结构化 JSON 输出和明确退出码。
- 对 HomePod 操作加跨进程文件锁；HTTP 服务使用动态端口和一次性随机路径。
- 临时语音放在单次私有目录，结束即删除；HTTP 服务只响应这一条媒体路径。
- 从 Home Assistant 地址动态推导可达的本机 LAN IP，仍允许环境变量覆盖。
- 播放前记录状态和音量；仅在必要的 AirPlay 复位流程中停止，完成后尽力恢复原播放和临时音量。
- 成功判断综合服务响应、媒体拉取和本次新增的解码错误；不把任意 HTTP 500 当作成功。
- 为 Home Assistant MCP 增加专用 HomePod 工具，不开放任意 media URL。
- 本次只覆盖短语音/TTS；按歌曲或 Apple Music 搜索不在范围内。

## 测试决策

- 使用本地假的 Home Assistant 服务验证完整调用，不触发真实设备。
- 验证临时媒体不可目录浏览、支持合法 Range、调用结束清理文件。
- 验证两个并发调用被串行化。
- 最后对真实 HomePod 播放一条短测试语音，检查结构化结果和设备状态。

## 不在范围内

- Apple Music 曲库搜索、选歌和歌单控制。
- 安装新的 Home Assistant 集成。
- 修改 HomePod 或 Apple 家庭的配对关系。
