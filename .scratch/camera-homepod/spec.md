# Camera to HomePod Explicit Link Spec

## 要解决的问题

Home Agent 分别能看客厅摄像头和让 HomePod 发声，但新会话不容易发现这两条能力，也没有一条清晰、安全的组合流程。

## 方案

给 Home Assistant MCP 增加一个只读的客厅摄像头快照工具，直接向模型返回图片。由主 Agent 在用户明确指令下看一张图、判断条件，再决定是否调用 HomePod 发声工具。

## 用户故事

- 作为用户，我想问“客厅有人吗”，让 Agent 单次看图回答。
- 作为用户，我想说“客厅有人就喊吃饭”，让 Agent 先看图，有人且判断明确时才播报。
- 作为用户，我想指定餐桌、沙发或门口机位，完成后镜头回到默认餐桌位。
- 作为用户，我不希望这个联动默认变成持续的人体追踪或人脸识别。

## 实现决策

- 快照工具只接受当前视角或已经登记的命名机位，不接受任意命令。
- 工具通过现有摄像头脚本抓图并返回 MCP 图片内容；不返回密码或 RTSP 地址。
- 非默认机位抓图后尽力回到餐桌默认位。
- Camera→HomePod 条件判断留在主 Agent 的视觉推理层，不在通道或后台记录器里硬编码业务规则。
- 只有用户明确提出当前联动或明确建立自动化时才执行；默认不持续识别人、不做人脸身份判断。

## 测试决策

- 模拟摄像头脚本，验证命名机位白名单、图片路径边界、工具注册和错误处理。
- 使用现有真实摄像头做一次只读快照确认；不额外触发 HomePod 播报。

## 不在范围内

- 人脸识别、身份库、行为追踪。
- 修改现有“在家不记录人的活动”的隐私规则。
- 默认启用入侵警报或自动喊话。
